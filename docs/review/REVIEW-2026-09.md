## Fixed on this branch

### 1. Homepage held a root-equivalent Docker socket, unauthenticated  — CRITICAL
`docker inspect homepage` showed `/var/run/docker.sock` bound **read-write**.
That socket is root-equivalent: anything that can talk to it can start a
privileged container and own the host. Homepage is a public-facing Next.js app,
so any RCE in it was a full host compromise.

It compounded: `curl http://192.168.1.100:3000` returned **HTTP 200 with no
auth**, while the same dashboard via Caddy correctly returned 401. The basic-auth
gate was bypassed by asking the port directly. Port 3000 was also absent from
`server_lan_only_published_ports`, so unlike every other service port it had no
guard rule at all.

Fixed: a filtered read-only socket proxy with POST denied, Homepage bound to the
LAN address, 3000 added to the guard.

*Checked and cleared:* the config's only credential-shaped hit (`proxmox.yaml`)
is the stock commented template. This was service-map disclosure, not credential
loss.

### 2. LAN-only firewall guard was TCP-only — MEDIUM
`autoconfig-docker-lan-guard.sh.j2` emitted `-p tcp` rules exclusively. Frigate
publishes 8555 on **both** protocols, so its WebRTC port sat on `0.0.0.0/udp`
with no filter while the TCP twin was guarded. Confirmed live: `ss -ulnp` showed
`0.0.0.0:8555` udp, `iptables -S DOCKER-USER | grep -c udp` returned 0.

### 3. Odoo — a business database with no backup at all — HIGH
`backup_database_dumps` covered aumenuilya, nextcloud and dinnizer. Odoo had **no
entry**. `/opt/odoo/db` is a live Postgres data directory, so the file-level copy
would be torn even if it were included, and the filestore is useless without the
database. Verified before fixing: password file present, database `odoo` exists,
`pg_dump` succeeds, **511 tables**.

Also added to `backup_paths` (each confirmed to exist on the host first):
`/etc/ansible/secrets` — the dumps were taken *against* those passwords, so
restoring onto a host that generated fresh ones yields a Nextcloud whose DB and
`config.php` disagree — plus `/opt/odoo/{app,addons,seed}`,
`/opt/jellyfin/config`, `/opt/game-timer/site`, `/opt/excalidraw`, `/etc/fstab`,
`/etc/netplan`.

### 4. The backup runner hid its own failures — HIGH
The dump loop was `if docker inspect <container> && [ -f <password> ]; then …
fi`. A typo in a container name **silently skipped that database** and the backup
still reported success — discoverable only at restore time. Missing container or
password file is now fatal.

Each dump also went straight to its final path with `>`, which truncates the
target before the command runs, so a failed dump destroyed the last good one.
Dumps now land in a `.partial` and move into place only when non-empty.

### 5. Unbounded container logs on a 94%-full disk — HIGH
No `/etc/docker/daemon.json`, no `log_options` anywhere. **946 MB** of container
logs had accumulated — frigate alone at 650 MB — on a filesystem with ~53 GB
free, with nothing to reclaim it. One crash-looping container fills that disk
overnight, and at 100% Postgres, MariaDB, Caddy and the Borg dump fail together.
Capped at the daemon so services added later inherit it.

### 6. Nothing could report a failure — HIGH
No `OnFailure=` on the pull unit or the Borg unit; a failed oneshot is entirely
silent. That is exactly how the nightly pull stayed broken for a day. Added
`autoconfig-notify` (base role, so every host gets it), wired via `OnFailure=`,
with the topic generated host-side into `/etc/ansible/secrets`.

Both units also gained `TimeoutStartSec`. Neither git nor apt has an internal
timeout, so a hung fetch left the unit `activating` forever — which never fires
`OnFailure` and is indistinguishable from a slow run.

### 7. No test could catch the bugs this repo actually ships
yamllint and ansible-lint passed while a folded scalar fed `python3 -c` an
indented first line and a systemd unit shipped a literal
`ExecStart={{ opencode_binary }}`. Neither looks at rendered output.
`tests/render_shell_templates.py` renders each shell template and shellchecks
it. Proven to catch a variable typo, surviving `{{ }}`, and SC2086 word
splitting — each verified by reintroducing the bug.

## Confirmed good — no action
Secrets hygiene is genuinely solid for a public repo: the vaulted file really is
`ANSIBLE_VAULT`-encrypted, `.gitignore` covers vault passwords, **zero
private-key blobs across all 3129 history objects**, no hardcoded credentials in
tracked files, and the historic `backups/raspi/*` Pi-hole configs carry no
password hash. The `AUTOCONFIG-LAN-ONLY` chain logic itself is correct.

## Open findings — not fixed, needs a decision

- **The repo is pull-only; the README documents a push command that cannot
  work.** `README.md` "Current Entry Points" offers
  `ansible-playbook --limit serverannah -e ansible_connection=ssh`. Two separate
  tasks break under it: `dotfiles_source_dir` uses `playbook_dir`, which resolves
  to the *control node's* path but is checked on the target; and the Odoo
  filestore uses `ansible.posix.synchronize`, which rsyncs **from** the control
  node. Either fix both or delete the claim.
- **The playbook cannot be dry-run end to end.** `--check` dies on Nextcloud's
  `occ status` wait ("Command would have run if not in check mode"). Worth a
  `when: not ansible_check_mode` guard on the wait loops so `--check` is usable
  as a pre-flight.
- **ufw is inactive on serverannah**; `DOCKER-USER` is the only filter. The
  workstation role has a firewall; the server does not.
- **Off-site backups.** Every copy is in one room — main SSD, backup disk,
  Timeshift SSD, Frigate disk. The rclone Google Drive remote already exists and
  is authorised; a `rclone sync` of the Borg repo after `borg compact` is the
  highest resilience-per-line change available. Borg segments are append-only, so
  the sync is cheap and safe.
- **The Borg passphrase exists on exactly one disk in one house.** Lose it and
  every archive, including any off-site copy, is permanently unreadable.

## Suggested next features, in value order
1. **Dead-man's switch** (healthchecks.io ping). `OnFailure=` catches a run that
   *fails*; it cannot catch a timer that never fires. Needs a watcher outside the
   house.
2. **Off-site Borg sync** over the existing rclone remote.
3. **Uptime Kuma** — ~150 MB, checks the 16 public sites, certs and DNS.
4. **Vaultwarden** — ~50 MB, and it solves the Borg-passphrase escrow problem.
5. **Tailscale for `ai.dinnizer.com` specifically.** opencode is an AI agent with
   shell access to the box, published on the internet behind a basic-auth
   password **shared with five other sites**. One leak from any of them is a
   shell. The README's reasoning for rejecting Tailscale for family-facing sites
   is sound and unchanged — this is the one service where it does not apply.

Explicitly not recommended here: Prometheus/Grafana/Loki (5-6 containers, 1-2 GB
RAM and unbounded disk to answer a question Uptime Kuma answers for 150 MB);
Immich (needs 200-500 GB, disk is at 94%); a real secrets manager (introduces an
unsealing bootstrap problem — the gap is escrow, not storage); Watchtower (fights
the role's deliberate image-pull ownership).
